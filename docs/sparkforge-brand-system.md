# SparkForge Brand System

## Positioning

SparkForge is the AI-powered Creator OS for people who want to discover what is worth building, make it, launch it and grow it from one workspace.

Core promise: **Find it. Forge it. Launch it. Grow it.**

Personality: capable, energetic, playful, premium, transparent and action-oriented.

SparkForge should feel like a creative studio with an autonomous specialist team—not a generic chatbot dashboard.

## Visual identity

### Primary mark

The SparkForge mark is an angular forge/spark symbol inside a compact hexagonal frame. The mark represents an idea entering the forge and leaving as something useful.

### Palette

| Token | Value | Role |
| --- | --- | --- |
| Spark Violet | #7657FF | Primary action and identity |
| Spark Cyan | #28D7FF | Technology, research, active states |
| Spark Pink | #FF4FB3 | Creativity, marketing, expressive accents |
| Spark Gold | #FFB84D | Product value, commerce and success moments |
| Spark Ink | #0B1020 | Premium dark contrast |
| Highlight | #D9FF66 | Selective emphasis and achievement |

Use violet as the dominant UI accent. Cyan and pink should create energy, not compete with primary actions. Gold is reserved for commerce/product moments.

## Typography

- Geist Sans for product UI and readable copy.
- JetBrains Mono for labels, metadata, status and technical chrome.
- Headlines should be confident and compact; avoid excessive all-caps marketing language.

## Fluffies

The Fluffy workforce is SparkForge's signature character system. Specialist agents receive distinct colors and role accessories while sharing the same face/silhouette language.

Never replace the SparkForge workforce with generic AI avatar stock art.

## Voice

Prefer:
- 'Let's find the opportunity.'
- 'Scout found a promising gap.'
- 'Forge turned it into a product blueprint.'
- 'Ready for your approval.'

Avoid:
- inflated claims such as 'guaranteed sales'
- fabricated market statistics
- robotic system-status language when plain language works
- pretending an action happened before it actually did

## Product principles

1. Evidence before hype.
2. Creation before configuration.
3. Show the work, not just the answer.
4. Humans approve consequential external actions.
5. Fluffies make the workforce memorable without hiding what each agent actually does.
6. Every important automation should have a visible state and recoverable failure path.
